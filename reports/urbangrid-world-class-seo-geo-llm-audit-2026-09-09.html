Critical findings

P0 — Public inspector data and password-hash exposure

An unauthenticated production request to /api/inspectors returned HTTP 200 with inspector records containing username, passwordHash, full name, email, and phone fields.

Action: Require admin authentication, return a restricted DTO, rotate affected credentials, and review access logs.

P0 — Hardcoded privileged credentials

Privileged admin and inspector credentials are embedded in server source. Values are intentionally omitted.

Action: Remove and rotate them, disable automatic default accounts, enforce managed secrets, and add MFA or managed identity.

P1 — 115 dependency vulnerabilities

2 critical, 46 high, 53 moderate, 14 low. Critical findings affect fast-xml-parser and have non-major fixes available. High findings include axios, drizzle-orm, nodemailer, rollup, ws, and postcss.

P1 — Invalid llms.txt

/llms.txt returns HTTP 200 with text/html and the homepage shell, not a plain-text LLM resource.

SEO Engine

What works

  • HTTPS, HTTP/2, HSTS, CSP, nosniff, clickjacking protection, referrer policy, and permissions policy.
  • Valid robots.txt with sitemap reference; sitemap covers core, service, location, and blog pages.
  • Route-specific titles, descriptions, canonicals, and JSON-LD are present in tested initial HTML.
  • Measured fresh TTFB was approximately 178 ms.

P1 — JavaScript-dependent body content

The server injects metadata, schema, and a hidden H1, but most useful copy and links arrive after React hydration. Pre-render the primary answer, evidence, FAQs, and internal links.

P1 — Duplicate H1 signals

Tested HTML contains a route-specific hidden H1 plus the generic hero H1. Use one visible, route-specific H1.

P1 — Inconsistent trust claims

Claims such as 40,000+ inspections, 600,000+ defects, 2,000+ clients, 10+ years, and review scores need consistent definitions and evidence.

P2 — Unsupported ratings and misleading location schema

Aggregate ratings lack visible supporting reviews. Emirate pages reuse a Dubai address. Remove unsupported ratings and distinguish genuine offices from service areas.

P2 — Broken social image and weak asset caching

The declared OG image resolves as HTML. Fingerprinted assets use private, max-age=0. Main JS is 403,503 bytes raw and main CSS is 204,329 bytes raw. Publish the image, add immutable caching, and reduce hydration cost.

GEO Engine

AI crawler access: strong

GPTBot, ChatGPT-User, ClaudeBot, Google-Extended, PerplexityBot, Bingbot, and Googlebot all received HTTP 200.

Citability: weak-to-moderate

  • Marketing claims often lack named sources, dates, or methodology.
  • Case studies need property details, tools, defect categories, totals, and outcomes.
  • Expert bylines, reviewer credentials, and authoritative sameAs profiles are limited.
  • Generic hero content reduces page-specific answer density.

Priority improvements

  1. Publish a valid llms.txt and a canonical content inventory.
  2. Lead priority pages with a 40–60 word direct answer.
  3. Use question-led headings, comparison tables, checklists, and concise FAQs.
  4. Cite named UAE regulators, standards bodies, dated sources, and expert reviewers.
  5. Publish evidence-rich inspection case studies and original datasets.

Security detail

Strengths

  • Strong baseline HTTP security headers.
  • Automated SAST returned no findings.
  • HoundDog returned five privacy/dataflow findings: one medium and four low.

Confirmed risks

  • Public inspector endpoint exposes PII and password-hash fields.
  • Hardcoded privileged credentials and a fallback session secret.
  • Session cookies explicitly configured with secure: false.
  • API response bodies and contact PII can be written to logs.
  • Unauthenticated conversation/model routes exist in source; live registration was not confirmed.

Prioritized action plan

First 24 hours

  1. Protect /api/inspectors and remove sensitive fields.
  2. Rotate and remove hardcoded credentials.
  3. Enforce the production session secret and secure cookie settings.
  4. Review endpoint access logs.

First 7 days

  1. Patch critical/high runtime dependencies and rescan.
  2. Publish llms.txt.
  3. Fix OG imagery.
  4. Remove unsupported ratings.
  5. Reconcile company claims.
  6. Stop logging PII and API bodies.

First 30 days

  1. Pre-render priority page content.
  2. Correct H1 and location schema.
  3. Add citable evidence, expert bylines, and dates.
  4. Add immutable asset caching.
  5. Launch a 20–30 prompt LLM benchmark.

60–90 days

  1. Publish original UAE inspection data and case studies.
  2. Earn relevant third-party citations.
  3. Strengthen verified entity/NAP profiles.
  4. Track non-branded ranking, AI mentions, citations, and leads monthly.
